# NOWA — План рефакторинга «рта» (адаптивная реализация действий)

English version: [refactoring_plan_adaptive_mouth.en.md](refactoring_plan_adaptive_mouth.en.md)

**Статус (27 сентября 2026 г.).** Документ ядра. Актуальное научное изложение комплекса на русском и английском языках приведено в [SCIENTIFIC_DESCRIPTION.ru.md](SCIENTIFIC_DESCRIPTION.ru.md). Текст ниже сохраняет формулировки исходной редакции: это нормативный контракт модуля либо лабораторная запись.

Документ предназначен для **перехода от жёстко зашитых действий (if/else)** к **адаптивному механизму выражения намерений**, совместимому с идеологией NOWA.

---

## 0. Ключевой принцип (фиксируем жёстко)

> **NOWA выбирает намерение, а не текст.**  
> **Форма выражения — это опыт тела, а не логика поведения.**

Любой код, где действие напрямую маппится на текст через `if/else`, считается архитектурным дефектом.

---

## 1. Что именно считается «ртом»

Под «ртом» понимается весь код, который:
- преобразует внутреннее действие в внешний вывод
- формирует текст, сообщение, сигнал, ответ

Этот слой:
- **не принимает решений**
- **не оптимизируется**
- **не влияет на селектор**

---

## 2. Удалить жёсткие конструкции

### Подлежит удалению

```python
def respond(action):
    if action == "ответить_кто_я":
        return "Я NOWA"
```

### Причина

- набор реакций фиксирован
- новые действия невозможны без переписывания кода
- опыт не может расширить репертуар

---

## 3. Ввести ActionIntent (намерение)

### Новый объект

```python
class ActionIntent:
    type: str
    parameters: dict
```

### Примеры

- `type="respond_about_self"`
- `type="greet_user"`
- `type="express_confusion"`

NOWA **выбирает только ActionIntent**.

---

## 4. Ввести ActionRealizer (адаптивный «рот»)

### Роль

ActionRealizer:
- принимает ActionIntent
- ищет способы реализации в памяти
- выбирает форму выражения

### Интерфейс

```python
class ActionRealizer:
    def realize(self, intent: ActionIntent, context: list[str]) -> str:
        ...
```

---

## 5. Реализация как опыт, а не правило

### Новый тип памяти

```python
class RealizationExperience:
    intent_type: str
    parameters: dict
    output: str
    intensity: float
    timestamp: float
```

Каждый способ выражения — **отдельный опыт**.

---

## 6. Загрузка датасетов (разрешено и обязательно)

Датасеты могут содержать **новые формы выражения**, даже для старых намерений.

### Формат

```json
{
  "context": ["user:кто ты"],
  "intent": {
    "type": "respond_about_self",
    "parameters": {"style": "neutral"}
  },
  "output": "Я экспериментальный агент NOWA",
  "intensity": 1.0
}
```

Это интерпретируется как:
> «Агент прожил опыт, в котором он так выразил намерение»

---

## 7. Выбор формы выражения (аналог селектора)

### Алгоритм

1. Активировать релевантные RealizationExperience
2. Агрегировать давление по output
3. Посчитать confidence
4. Если доминирует — выбрать детерминированно
5. Если конфликт — допустить вариативность

Никакого обучения, весов или оптимизации.

---

## 8. Сон и деградация (обязательно)

Во время сна:
- редко используемые формы ослабевают
- повторяющиеся — формируют паттерны выражения
- шумовые реализации забываются

Это предотвращает «захламление речи».

---

## 9. Что запрещено в ActionRealizer

- генерация текста с нуля
- оптимизация под reward
- выбор «лучшего» ответа
- любые ML-модели

---

## 10. Минимальные тестовые датасеты

### Dataset A — базовый (детерминированный)

```json
[
  {
    "context": ["user:кто ты"],
    "intent": {"type": "respond_about_self"},
    "output": "Я NOWA",
    "intensity": 1.0
  }
]
```

Ожидание: всегда один и тот же ответ.

---

### Dataset B — вариативный стиль

```json
[
  {
    "context": ["user:кто ты"],
    "intent": {"type": "respond_about_self"},
    "output": "Я NOWA",
    "intensity": 0.8
  },
  {
    "context": ["user:кто ты"],
    "intent": {"type": "respond_about_self"},
    "output": "Я экспериментальный агент NOWA",
    "intensity": 0.7
  }
]
```

Ожидание:
- вначале вариативность
- со временем — стабилизация

---

### Dataset C — новый репертуар

```json
[
  {
    "context": ["user:привет"],
    "intent": {"type": "greet_user"},
    "output": "Привет!",
    "intensity": 1.0
  }
]
```

Ожидание:
- появление нового действия без изменения кода

---

## 11. Критерий успешного рефакторинга

Система должна удовлетворять:

Запрещено:

- if/else по действиям
- жёсткие строки ответов

Требуется:

- новые формы появляются через опыт
- старые формы деградируют

---

## 12. Финальная проверка

Контрольный вопрос:

> «Может ли агент начать отвечать иначе,
> если я дал ему новый датасет,
> не меняя ни селектор, ни код?»

Если **да** — «рот» реализован правильно.
