## 1. Проблема

После внедрения replay, делиберативного планирования и политики, управляемой неопределённостью, возникает эффект **коллапса присвоения кредита**.

**Симптомы:**

1. вознаграждение распределяется на слишком ранние состояния
2. TD-error распространяется по длинной цепочке
3. replay усиливает ложные корреляции
4. EDPC начинает переоценивать случайные действия

**В результате:** дрейф политики, неустойчивые привычки, колеблющиеся оценки ценности.

---

## 2. Причина

В текущей архитектуре:

```
reward → TD update → replay → EDPC stability
```

Нет механизма, ограничивающего глубину распространения кредита.

---

## 3. Решение

Вводятся три механизма:

- Temporal Credit Window
- Eligibility Traces
- Replay Causality Filter

---

## 4. Временное окно кредита

### 4.1 Определение

Вознаграждение может распространяться только на ограниченное число предыдущих состояний:

```
credit_window = 6
```

### 4.2 Ограничение

```
reward propagation depth ≤ credit_window
```

### 4.3 Реализация

Обновления TD должны применяться только к последним N событиям в `Path.events`, где `N = credit_window`.

---

## 5. Следы пригодности

### 5.1 Определение

Каждой паре состояние–действие присваивается след:

```
eligibility_trace ∈ [0, 1]
```

### 5.2 Обновление следа

При выполнении действия: `trace = 1`.
Для остальных:

```
trace ← trace * λ
```

### 5.3 Параметры

```
λ = 0.85
```

### 5.4 Обновление TD

```
ΔV = α * TD_error * eligibility_trace
```

### 5.5 Ограничение

```
trace ≤ 1
```

---

## 6. Фильтр причинности replay

Replay не должен усиливать ложные корреляции.

### 6.1 Условие replay

Эпизод допускается к replay только если:

```
causality_score ≥ threshold
```

### 6.2 Формула

```
causality_score =
    reward_magnitude
    * (1 - state_distance)
    * action_stability
```

Где: `state_distance = normalized_state_delta`, `action_stability = SAC stability_score`.

### 6.3 Порог

```
causality_threshold = 0.15
```

---

## 7. Затухание обратного распространения вознаграждения

Вознаграждение должно ослабевать по времени.

### 7.1 Формула

```
credit_weight(step) = exp(-step / τ)
```

### 7.2 Параметр

```
τ = 3
```

### 7.3 Ограничение

```
credit_weight ≥ 0.05
```

---

## 8. Шлюз устойчивости replay

Replay должен усиливать только стабильные знания.

### 8.1 Условие

```
replay_allowed if stability_score > 0.25
```

### 8.2 Исключение

Если `prediction_shock_score > 0.7` — replay разрешён независимо от устойчивости.

---

## 9. Обрезка ошибки TD

Чтобы избежать неуправляемого роста TD.

### 9.1 Ограничение

```
TD_error ∈ [-1.0, 1.0]
```

### 9.2 Применение

Применяется к онлайн-обновлению и к replay во сне.

---

## 10. Ограничение разнообразия replay

Replay не должен повторять одну и ту же пару состояние–действие.

```
max_replay_per_state = 3   # за один sleep цикл
```

---

## 11. Учёт причинности в памяти

Каждый опыт должен хранить `causal_depth`.

### 11.1 Определение

```
causal_depth = distance_from_reward_event
```

### 11.2 Ограничение

```
causal_depth ≤ credit_window
```

---

## 12. Интеграция с DecisionArbitrator

### 12.1 Новая метрика

```
policy_reliability =
    mean(action_stability)
    * (1 - global_uncertainty)
    * mean(causality_score)
```

### 12.2 Использование

Если `policy_reliability < 0.35` — принудительно включается режим `DELIBERATIVE`.

---

## 13. Ограничения

| Параметр             | Ограничение             |
|----------------------|-------------------------|
| Затухание следа `λ`  | `∈ [0, 1]`              |
| `credit_window`      | `∈ [3, 10]`             |
| `causality_score`    | `∈ [0, 1]`              |
| Обрезка TD           | `|TD_error| ≤ 1`        |

---

## 14. Телеметрия

Телеметрия агента должна содержать:

- `eligibility_trace_mean`
- `credit_window_usage`
- `replay_causality_mean`
- `policy_reliability`

---

## 15. Тест-кейсы

### ТЕСТ 1 — Вознаграждение длинной цепочки

**Вход:** эпизод из 10 шагов, вознаграждение на шаге 10.

**Ожидается:** обновлены только последние 6 состояний.

### ТЕСТ 2 — Затухание следа

**Вход:** `λ = 0.85`.

**Ожидается:** монотонное убывание: `1.0 → 0.85 → 0.72 → 0.61`.

### ТЕСТ 3 — Фильтр причинности replay

**Вход:** `reward = 0.2`, `state_distance = 0.8`, `stability = 0.4`.

**Оценка:**

```
0.2 * (1 - 0.8) * 0.4 = 0.016
```

**Ожидается:** replay отклонён.

### ТЕСТ 4 — Перекрытие шоком

**Вход:** `shock_score = 0.8`, `stability = 0.1`.

**Ожидается:** replay разрешён.

### ТЕСТ 5 — Обрезка TD

**Вход:** `TD_error = 3.5`.

**Ожидается:** `TD_error = 1.0`.

### ТЕСТ 6 — Коллапс надёжности политики

**Вход:** `uncertainty = 0.7`, `stability = 0.3`, `causality = 0.2`.

**Ожидается:** `policy_reliability < 0.35`, `mode = DELIBERATIVE`.

---

## 16. Критерии приёмки

Изменение считается успешным если:

1. распространение TD ограничено
2. replay не усиливает ложные цепочки
3. политика не коллапсирует при редком вознаграждении
4. оценки ценности стабилизируются

---

## 17. Результат архитектуры

После внедрения SPEC-011 и SPEC-011A система получает:

- политику, учитывающую неопределённость
- устойчивое присвоение кредита
- управляемое обучение через replay
- обобщённую память состояний
