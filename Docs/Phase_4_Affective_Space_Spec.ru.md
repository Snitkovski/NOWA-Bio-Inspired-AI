## Формальная спецификация аффективного пространства (до чувств)

### Цель

Создать непрерывное, многомерное аффективное пространство, в котором:
- чувства не являются флагами или классами,
- допустимы противоречивые и навязчивые состояния,
- субъективность и характер возникают естественно из динамики,
- архитектура совместима с предыдущими фазами (3, 3.5, 3.75).

---

## 1. Общая модель

Аффективное состояние агента описывается вектором **A(t)** в пространстве ℝ⁸.

Каждая ось независима, имеет собственную динамику, инерцию и шум.

Никакой нормализации суммы значений не применяется.

---

## 2. Оси аффективного пространства (8)

Все оси имеют диапазон **[0.0 .. 1.0]**.

| Ось | Описание |
| --- | --- |
| pleasure | удовольствие / положительная гедоника |
| pain | боль (не отрицательное удовольствие) |
| arousal | возбуждение / активация |
| relaxation | расслабление |
| attachment | привязанность |
| rejection | отторжение |
| focus | фокус / когнитивная фиксация |
| vulnerability | уязвимость / открытость к воздействию |

Все оси **равноправны**.  
Любая ось может участвовать в любом чувстве.

---

## 3. Базовая динамика оси

Для каждой оси `i`:

```text
dA_i/dt =
    input_i
  - decay_i * A_i
  + inertia_i
  + noise_i
```

---

## 4. Инерция (ключ к навязчивости)

Навязчивость не ошибка. Это параметр.

```text
навязчивость_i =
    высокая inertia_i
  + низкий fall_rate_i
  + высокий focus
```

---

## 5. Шум

Шум необходим для субъективности.

```text
noise_i ~ N(0, σ_i)
```

σ зависит от:
- wakefulness
- uncertainty
- конфликтов осей

---

## 6. Метрики

1. Расстояние:

```text
D(A,B)=Σ w_i|A_i-B_i|
```

2. Скорость:

```text
V=|A(t)-A(t-1)|
```

## 7.1 Примечание реализации (Agent)

В базовой реализации (Agent) связь `reward → pain` сделана контекстной:

```text
pain = clamp(
    max(0.0, -reward) * intensity * (0.5 + 0.5 * vulnerability)
)
```

Это означает:
- при высокой уязвимости боль усиливается,
- при устойчивости негативный reward не всегда эквивалентен боли.
