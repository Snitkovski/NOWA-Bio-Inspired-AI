## Примечание к реализации (3 марта 2026 г.)

Поведение SAC во время выполнения расширено разделением фаз SWS/REM/TRANSITIONAL и строгими жёсткими ограничениями.
Канонические правила фаз документированы в:
- `Docs/spec_sws_rem_phase_separation.md`

Текущие дополнения времени выполнения, согласованные с кодом и тестами:
- глобальный и необязательный локальный режим фазы (`local_phase_mode`)
- жёсткие ограничения: `sac_alpha_slow <= 0.01`, `sac_alpha_base <= 0.01`, `sac_lambda_sws > sac_lambda_rem`
- явное правило одной фазы на действие (`SWS xor REM xor TRANSITIONAL`)
- нижняя граница устойчивости REM (`sac_stability_floor_rem`)
- сброс спокойного цикла структурного оповещения (`sac_structural_alert_reset_cycles`)
- потолок шага семантической уверенности за цикл (`sac_semantic_confidence_step_cap`)


**Версия:** 1.1  
**Статус:** интегрировано во время выполнения (`SleepManager`, только сон)  
**Назначение:** Медленная консолидация семантической модели действий из стабильного эпизодического опыта во время сна.

---

## 1. Цель модуля

Обеспечить:

- Медленное обновление `action_metadata`
- Защиту от смещения подтверждения
- Устойчивость к аномалиям (высокий `prediction_shock`)
- Двухскоростную динамику (эпизодическая быстрая / семантическая медленная)
- Биологически правдоподобную консолидацию, открываемую сном

---

## 2. Область ответственности

SAC:

- Работает **только во время сна**
- Обновляет **только семантический слой**
- Использует агрегированные сигналы воспроизведения
- Не вмешивается в online TD

---

## 3. Входные данные

### 3.1 Из Hippocampus 2.0 (буфер воспроизведения)

Для каждого эпизода воспроизведения:

```
action_id
TD_error
prediction_shock
confidence_score
stability_score
observed_outcome
predicted_outcome
consolidation_probability
```

### 3.2 Из ValueLayer (семантическое хранилище)

```python
action_metadata[action_id] = {
    expected_effect_mean,    # μ
    expected_effect_variance, # σ²
    success_alpha,
    success_beta,
    risk_estimate,
    semantic_confidence
}
```

---

## 4. Гейтинг консолидации

Эпизод допускается к семантическому обновлению, если:

```
confidence_score       > θ_conf
stability_score        > θ_stab
prediction_shock       < θ_shock
consolidation_probability > θ_cons
```

**Рекомендуемые пороги:**

| Порог      | Значение |
|------------|----------|
| `θ_conf`   | 0.6      |
| `θ_stab`   | 0.5      |
| `θ_shock`  | 0.4      |
| `θ_cons`   | 0.5      |

> Если условие не выполнено, эпизод игнорируется.

---

## 5. Агрегация сигнала

Для каждого `action_id`:

1. Собрать все допущенные эпизоды воспроизведения.
2. Рассчитать вес эпизода:

```
w_i = stability_score_i × confidence_score_i × (1 - prediction_shock_i)
```

3. Рассчитать:

```
TD_semantic       = weighted_mean(TD_error_i, w_i)
μ_observed        = weighted_mean(observed_outcome_i, w_i)
σ_observed        = weighted_variance(observed_outcome_i, w_i)
success_rate_obs  = weighted_mean(success_flag_i, w_i)
```

> Если суммарный вес меньше `θ_min_weight`, обновление пропускается.

---

## 6. Обновление семантической модели

### 6.1 Двухскоростной коэффициент обучения

```
α_fast  ∈ [0.05, 0.2]    # episodic, не в SAC
α_slow  ∈ [0.001, 0.01]  # semantic, используется в SAC
```

### 6.2 Обновление ожидаемого эффекта

```
μ_new = μ_old + α_slow * (μ_observed - μ_old)
```

### 6.3 Обновление дисперсии

```
σ²_new = σ²_old + α_slow * (σ²_observed - σ²_old)
σ²_new = max(σ_floor, σ²_new)
```

Правило адаптации:

- если средний шок по эпизодам больше 0.3, `σ²` увеличивается дополнительно на `ε_var`
- если стабильность высока, `σ²` уменьшается
- защита от кристаллизации: `σ_floor ≈ 0.01` (защита от семантической кристаллизации)

### 6.4 Обновление вероятности успеха (бета-модель)

```
success_alpha_new = success_alpha_old + α_slow * weighted_successes
success_beta_new  = success_beta_old  + α_slow * weighted_failures
```

### 6.5 Обновление риска

```
risk_estimate_new = f(σ²_new, failure_rate)
```

Где:

```
risk_estimate ∝ σ² × failure_probability
```

---

## 7. Ограничение против смещения подтверждения

Семантическое обновление разрешено только если:

```
|μ_old - μ_observed| > ε_divergence
```

Где `ε_divergence ≈ 0.05–0.1` (в нормированной шкале).

> Если расхождение мало, обновление подавляется.

---

## 8. Ограничения (жёсткие ограничения)

- SAC не может вызываться в состоянии бодрствования
- SAC не может изменять эпизодические значения
- `α_slow ≤ 0.01` — жёсткий предел
- Если `prediction_shock_mean > 0.6`, обновление запрещено
- Если `replay_count < N_min` (например 3), обновление запрещено

---

## 9. Инварианты системы

После любого шага SAC:

- `σ²_new ≥ σ_floor` (`σ_floor` по умолчанию `0.01`)
- `success_alpha > 0`
- `success_beta > 0`
- `risk_estimate ∈ [0, 1]`
- `semantic_confidence ∈ [0, 1]`

---

## 10. Метрики для мониторинга

- Темп семантического дрейфа
- Темп роста стабильности
- Индекс снижения расхождения
- Индекс избыточной уверенности

---

## 11. Тест-кейсы

### Тест 1 — Подтверждённое действие

**Дано:** 10 эпизодов воспроизведения, низкий шок, высокая стабильность, `μ_observed > μ_old`.

**Ожидается:** `μ_new > μ_old`, `σ²_new` уменьшается, `success_alpha` увеличивается, `risk_estimate` уменьшается.

### Тест 2 — Аномальный эпизод

**Дано:** высокий `prediction_shock` (> 0.7).

**Ожидается:** обновление не выполняется, семантический слой неизменен.

### Тест 3 — Недостаточно данных

**Дано:** `replay_count = 1`.

**Ожидается:** обновление не выполняется.

### Тест 4 — Высокая нестабильность

**Дано:** `stability_score < θ_stab`.

**Ожидается:** эпизод исключён из агрегации.

### Тест 5 — Расхождение мало

**Дано:** `|μ_old - μ_observed| < ε_divergence`.

**Ожидается:** `μ` не изменяется.

### Тест 6 — Катастрофический дрейф

**Дано:** `α_slow` искусственно установлен равным 0.1.

**Ожидается:** система отклоняет конфигурацию (нарушение жёсткого ограничения).

### Тест 7 — Расширение дисперсии под действием шока

**Дано:** средний шок = 0.4.

**Ожидается:** `σ²_new > σ²_old`.

### Тест 8 — Нижняя граница дисперсии (защита от кристаллизации)

**Дано:** `σ²_old` очень мала (`< 0.01`) и стабильность высока.

**Ожидается:** после SAC `σ²_new ≥ σ_floor`.

## 12. Режимы отказа

| Режим сбоя                         | Мониторинг                        |
|------------------------------------|-----------------------------------|
| Семантическая ригидность           | Индекс снижения расхождения       |
| Семантический дрейф                | Темп семантического дрейфа        |
| Коллапс избыточной уверенности     | Индекс избыточной уверенности     |
| Усиление смещения воспроизведения  | Темп роста стабильности           |

> Каждый должен отслеживаться метриками из раздела 10.

---

## 13. Итоговая архитектурная позиция

SAC обеспечивает:

- сохранение агента как обучающегося организма
- постепенное формирование долговременных способностей
- устойчивость к шуму среды
- возможность учиться из внешних данных
- возможность предсказывать мир

> Без превращения системы в статичную модель мира.
