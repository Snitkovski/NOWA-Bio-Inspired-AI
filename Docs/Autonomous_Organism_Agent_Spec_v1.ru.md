## 1. Назначение

Задать автономное непрерывное поведение, включающее:
- внутренний цикл времени
- ограниченные драйвы и энергию
- внутреннее моделирование с учётом аффекта
- управляемую речь
- строгие инварианты и журналирование

Эта среда выполнения интегрирует существующие модули через управляемые интерфейсы и не обходит архитектуру базового агента.

## 3. Модель времени

Состояние:
- `t_current`
- `t_last_tick`
- `dt > 0`

Цикл такта:
```text
while alive:
    dt = now - t_last_tick
    organism_step(dt)
    sleep(min_interval)
```

---

## 4. Таксономия драйвов (текущая)

Все драйвы ограничены интервалом `[0, 1]`:
- `curiosity`
- `social_drive`
- `goal_tension`
- `exploration`
- `energy_need`

Не являются драйвами:
- `self_reflection` представлен значением `agent_mode="REFLECTION"`
- `emotional_discharge` представлен путём запуска аффективной регуляции

Обновление драйва (ограниченное):
```text
drive(t+dt) = drive(t)
           + accumulation*dt
           + affect_modulation
           - discharge*dt
           - decay*dt
```

---

## 5. Модель энергии

Состояние:
- `energy` в `[0,1]`
- `fatigue` в `[0,1]`

Обновление:
```text
energy -= cognitive_cost * dt
energy += recovery_rate * rest_time
```

Если энергия ниже порога, внутренние циклы подавляются.

---

## 6. Цикл внутреннего моделирования

Запуск:
```text
max(drive_i * weight_i) > threshold
```

Ограничения:
1. Используются только гипотетические копии состояния.
2. Живое состояние не должно изменяться во время оценки.
3. Не более одного внутреннего цикла на такт.
4. Число внутренних циклов в окне жёстко ограничено.

Конвейер:
1. ограниченное извлечение из памяти
2. порождение гипотез
3. предложение действия
4. гипотетическое моделирование действия
5. оценка полезности
6. ранжирование вариантов

Разделение предложения и оценки:
- предлагающий: `ActionSelector.choose(...)`
- оценивающий: `ActionSelector.evaluate(hypothetical_state)` (только полезность)

Общая полезность:
- сосредоточена в `src/simulation_utility.py`
- переиспользуется селектором и средой моделирования

Затравка драйва для гипотетического состояния:
- берётся из снимка живой `DriveSystem`, когда он доступен
- принудительное `active_drive=1.0` не задаётся

Контракт выхода:
```json
{
  "best_action": "string",
  "confidence": 0.0,
  "evaluated_variants": 0
}
```

## 7. Регулятор речи

Речь допустима только если:
- драйв коммуникации выше порога
- релевантность выше минимума
- период охлаждения истёк
- предел интервала не превышен

Инвариант периода охлаждения обязателен.

---

## 8. Аффективная регуляция и режим

Значения `agent_mode`:
- `IDLE`
- `ACTIVE`
- `REFLECTION`

Режим `REFLECTION` включается при низкой внешней стимуляции и высоких сигналах ошибки предсказания или неопределённости.

Аффективная регуляция:
- запускается порогом перегрузки
- снижает интенсивность аффекта и перегрузку
- не создаёт драйвов
- не участвует в ранжировании драйвов

---

## 9. Основные инварианты

1. Аффективное ядро изменяется только через определённый интерфейс аффекта.
2. Драйвы остаются в `[0,1]`.
3. Энергия и усталость остаются в `[0,1]`.
4. Устаревшие мета-драйвы отсутствуют.
5. Период охлаждения речи соблюдается.
6. Внутреннее моделирование не оценивает живое состояние напрямую.

Нарушение журналируется как отказ времени выполнения.
