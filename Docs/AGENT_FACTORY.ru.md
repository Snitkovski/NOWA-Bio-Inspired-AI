## Область

`src/agent_factory.py` реализует фабрику с единой точкой входа для создания агентов NOWA в эволюционных процедурах.

Основные цели:
1. построить полностью инициализированный `Agent` из `GenomeVector`
2. при необходимости внедрить унаследованную память из `EpigenomeSnapshot`
3. поддержать порождение потомства от родителей (`spawn_child`)
4. предоставить устойчивые интерфейсы извлечения (`extract_genome`, `extract_epigenome`)
5. сохранить устойчивость создания агента (некорректные полезные нагрузки не обрушивают пути фабрики)

## Реализованные объекты

### `AgentConfig`

Конфигурация уровня среды:
- `actions`
- `hippocampus_capacity`
- `cortex_capacity`
- `sleep_cycles_default`
- `intent_memory_enabled`
- `environment_id`
- `base_lifespan_steps`

### `AgentFactory`

Основные открытые методы:
- `spawn(genome, epigenome=None, epigenome_noise=0.1, rng=None, agent_id="")`
- `spawn_random(rng=None, agent_id="")`
- `spawn_default(agent_id="")`
- `spawn_child(parent_a, parent_b, ..., rng=None, agent_id="")`
- `extract_genome(agent)`
- `extract_epigenome(agent, ..., min_confirmation=1.0)`

## Поведение порождения

Последовательность `spawn(...)`:
1. разрешить геном (при отсутствии — `GenomeVector.default()`)
2. развернуть параметры через `genome.to_agent_params()`
3. построить модули (`hippocampus`, `cortex`, `selector`, `sleep_manager`, `wakefulness`)
4. сконструировать `Agent`
5. применить после инициализации геномные переопределения к модулям времени выполнения
6. присоединить метаданные фабрики:
   - `agent.genome`
   - `agent.epigenome`
   - `agent.agent_id`
   - `agent.lineage_id`
   - `agent.factory_config`
7. присоединить эволюционные подсистемы:
   - `agent.reproductive_system`
   - `agent.mortality_system`
   - `agent.expected_lifetime_steps` (выводится из фактора продолжительности жизни генома)
8. если эпигеном задан, выполнить безопасное внедрение до шага

Ограничения безопасности:
1. `epigenome_noise` ограничивается диапазоном `[0.0, 1.0]`
2. некорректная полезная нагрузка эпигенома не обрушивает порождение
3. сбои применения отдельных параметров выдают `warnings.warn(...)` и исполнение продолжается

## Порождение потомка

Поведение `spawn_child(...)`:
1. извлекает геномы обоих родителей (с запасным восстановлением)
2. выполняет кроссовер (`arithmetic` / `uniform` / `sbx`) с ограниченными аргументами
3. сохраняет один дочерний геном
4. применяет мутацию с ограниченными `mutation_rate` и `sigma_scale`
5. при необходимости смешивает эпигеномы родителей
6. передаёт окончательное создание методу `spawn(...)`

Запасное поведение:
1. родитель без корректного `genome` → путь восстановленного или генома по умолчанию
2. родитель без корректного `epigenome` → `EpigenomeSnapshot.empty()`
3. недопустимый режим кроссовера → запасной арифметический режим

## Извлечение и круговой проход

### `extract_genome(agent)`

1. возвращает `agent.genome`, если он присутствует и корректен
2. иначе восстанавливает геном из живых параметров модулей

### `_reconstruct_genome(agent)`

Восстанавливает гены из:
- матрицы взаимодействия нейромодуляторов и параметров ACC
- параметров затухания и регуляции аффективного пространства
- скоростей бодрствования и циркадного ритма
- автономных драйвов, порогов и энергии времени выполнения
- параметров слоя ценности и TD
- порогов hippocampus и сна
- параметров воображения

Соглашение о матрице нейромодуляторов явно и общее для путей записи и чтения:
- матрица используется как `W[target][source]`
- одна таблица отображения используется в обоих:
  - `_apply_neuromodulator_overrides(...)`
  - `_reconstruct_genome(...)`

Это предотвращает дрейф соглашения об индексах в круговом проходе геном → агент → геном.

### `extract_epigenome(agent)`

Использует открытое состояние модулей для построения словарей и делегирует:
- `EpigenomeSnapshot.extract(...)`

Источники:
- паттерны `agent.cortex`
- `agent.selector.action_metadata`
- `agent.value_layer.expectation_memory`
