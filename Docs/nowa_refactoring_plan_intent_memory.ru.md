# NOWA — План рефакторинга IntentMemory (память намерений)

Документ описывает **недостающий слой архитектуры NOWA**, необходимый для корректной работы селектора **без обучения и весов**.

---

## 0. Зачем нужен этот слой (фиксируем причину)

После удаления обучения селектора система стала:
- честной
- недетерминированной при конфликте
- но **потеряла устойчивость привычных реакций**

Причина:
> отсутствует память связей «контекст → намерение».

`IntentMemory` **не обучает поведение**, а **накапливает привычки**.

---

## 1. Онтологическое место IntentMemory

```
Context
  ↓
IntentMemory  ← (формируется из опыта)
  ↓
Selector (stateless)
  ↓
ActionIntent
```

`IntentMemory`:
- не выбирает
- не оптимизирует
- не реализует действия

Она **создаёт давление привычки**.

---

## 2. Новый объект: IntentTrace

### Структура

```python
class IntentTrace:
    intent_type: str
    context_signature: str
    strength: float
    recency: float
    timestamp: float
```

### Смысл полей

- `intent_type` — что обычно делается
- `context_signature` — когда это делается
- `strength` — частота и устойчивость
- `recency` — свежесть

Нет подкрепления, нет весов, нет градиентов.

---

## 3. Формирование IntentTrace

`IntentTrace` создаётся:
- при каждом завершённом `Experience`
- из пары:

```
(context, action_intent)
```

Если след с таким же `context_signature + intent_type` уже есть:
- `strength += 1`
- `recency = now`

Если нет:
- создаётся новый

---

## 4. Активация IntentMemory

При новом входном контексте:

1. вычисляется `context_signature`
2. активируются все `IntentTrace` с похожей сигнатурой
3. рассчитывается давление:

```
pressure = strength × recency_decay × context_similarity
```

Результат — **распределение давления по `intent_type`**.

---

## 5. Передача в селектор

Селектор получает:

```python
{
  intent_type_1: pressure_1,
  intent_type_2: pressure_2
}
```

И:
- если есть доминирование → детерминированный выбор
- если конфликт → вариативность

Селектор по-прежнему не обучается.

---

## 6. Сон и IntentMemory (обязательно)

Во время сна:

- редко используемые следы ослабевают
- повторяющиеся укрепляются
- конфликтные могут сливаться

Это формирует:
> «обычно в такой ситуации я делаю вот это»

---

## 7. Что IntentMemory не делает

Запрещено:

- выбирать действие
- хранить текст
- оптимизировать результат
- иметь подкрепление

`IntentMemory` — это **память привычек, а не интеллект**.

---

## 8. Минимальные тестовые сценарии

### Сценарий A — привычка формируется

Датасет:
```json
[
  {"context": ["user:кто ты"], "intent": "respond_about_self"},
  {"context": ["user:кто ты"], "intent": "respond_about_self"},
  {"context": ["user:кто ты"], "intent": "respond_about_self"}
]
```

Ожидание:
- уверенный, детерминированный выбор

---

### Сценарий B — конфликт привычек

```json
[
  {"context": ["user:кто ты"], "intent": "respond_about_self"},
  {"context": ["user:кто ты"], "intent": "greet_user"}
]
```

Ожидание:
- пониженная уверенность
- вариативность

---

## 9. Критерий корректной реализации

Система должна:

- не иметь обучения селектора
- не иметь весов
- стабилизироваться при повторе
- сомневаться при конфликте

---

## 10. Контрольный вопрос

> «Если я полностью заморожу селектор, но продолжу давать опыт — изменится ли поведение?»

Если **да** — `IntentMemory` реализована правильно.
