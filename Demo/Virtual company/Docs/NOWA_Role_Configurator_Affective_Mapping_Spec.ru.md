## Аннотация

English version: [NOWA_Role_Configurator_Affective_Mapping_Spec.en.md](NOWA_Role_Configurator_Affective_Mapping_Spec.en.md)

Спецификация версии 1.1 закрывает отложенный блок вкладки эмоциональных реакций и приводит карту роли к канону аффективного состояния. Вектор A(t) содержит восемь осей, каждая в отрезке [−1, 1]: валентность, возбуждение, доминантность, стресс, доверие, любопытство, устойчивость и привязанность. YAML описывает импульс к именованному событию, а не второй вектор чувств. Хозяин, интерфейс, кодировщик и сухой прогон не присваивают оси; допустимы `EmotionalImpulse` и `step`. Деньги и срочность осями не являются и остаются тегами. Подписи `joy`, `sadness`, `love`, `hate`, `fear` и `pleasure_rest` вычисляются из осей слоем семантических эмоций и в селектор и в `SchemaBinder` не поступают. Чтения `decision_bias()` — риск, скорость ответа, выбор слов, эмпатия и приоритет цели — и `rank_weights()` — осторожность, неприятие цены, поиск скорости, надёжность, поиск новизны и напористость — в YAML не задаются. Источник импульса события мира всегда `external`. Хозяин сотрудника новые оси не добавляет.

Запись реализации на 31 августа 2026 года с этим каноном расходится. Парсер `_parse_affective_mapping` сохраняет только валентность, возбуждение и теги и отбрасывает остальные оси. Флаг `ADVANCED_AFFECT_AXES_ENABLED` выключен, и кнопка расширенной настройки скрыта. `GenericEncoder` при совпадении имени события выпускает токены контекста, а импульс из карты почти не строит: эвристические импульсы ограничены ошибкой или таймаутом, ростом цены, падением количества и новизной. Сравнение ролей при слиянии смотрит на валентность, возбуждение и теги, поэтому одинаковая пара валентность/возбуждение при разном стрессе сливается без конфликта. Сокращённый слайдер возбуждения пишет отрезок [0, 1], тогда как ось канона есть [−1, 1]. Четыре пресета зашиты в контроллере и содержат только эту пару; пользовательского справочника нет.

Фаза A в одном цикле реализации расширяет разбор и обратную запись на все восемь осей и на интенсивность, отвергает неизвестный ключ ошибкой `RoleConfigError` с путём к полю и без тихого отбрасывания, и заставляет сработавшую карту эмитировать `EmotionalImpulse`. Опущенная ось не означает нуль и в файл при сохранении не дописывается. Интенсивность по умолчанию равна 0,35, лежит в [0, 1] и на наложении чтения дополнительно ограничивается сверху значением 0,4. Пресеты переносятся в отдельный YAML-справочник поставки и пользовательских записей; клик заполняет полный канонический вектор. Слияние сравнивает полную запись. Фаза B, не блокирующая приёмку фазы A, показывает на карточке запущенного сотрудника снимок восьми осей, три верхние семантические метки и численные чтения смещения решения и весов ранжирования из уже существующей `EmployeeSession`, без второго состояния и без пересоздания виджетов на каждом тике. Сухой прогон роли сессию сотрудника не запускает. Новых осей, полей удовольствия и боли в роли и переписывания `affective_space.py` спецификация не допускает. Векторы исхода по статусу MCP остаются платформенными.

## 0. Зачем эта спецификация

Сейчас вкладка выглядит как «полный аффект», но за ней стоит **урезанный
shorthand**. Пользователь двигает valence/arousal, а канон NOWA — восемь
осей, импульсы, bias, ranking и семантические ярлыки. Без этой поставки
роль не может выразить то, чем сотрудник уже умеет пользоваться в ядре.

| Что пользователь видит / ожидает | Что есть as-built (2026-08-31) |
|---|---|
| Событие мира → чувство сотрудника | Только `valence` + `arousal` + `tags` в YAML |
| Восемь осей AffectiveSpace | Парсер `_parse_affective_mapping` **выбрасывает** любые другие оси |
| Кнопка «Продвинутая настройка» | `ADVANCED_AFFECT_AXES_ENABLED = False`, кнопка скрыта |
| Событие реально *сдвигает* A(t) | `GenericEncoder` почти не эмитит импульс из маппинга: overlay даёт **токены**, heuristic-импульсы — только error / cost↑ / quantity↓ / novelty |
| «Насколько это изменит решение» | Нет превью `decision_bias()` / `rank_weights()` |
| Слова «страх / радость» | Нет; и **не должны** стать управляющим сигналом (P9) |
| Живой A(t) у запущенного сотрудника | Карточка сотрудника оси не показывает |
| Свои пресеты «кризиса» | `AFFECT_PRESETS` — четыре id в Python, только VA; пользовательский справочник отсутствует |

Эта спецификация закрывает разрыв **не переписывая ядро**. Новых осей нет.
Новых эмоций-контроллеров нет. Outcome-векторы MCP status остаются
платформенными (`AffectiveSpace.outcome_impulse`).

## 1. Канон, который нельзя нарушить

Копия правил из `spec_affective_space_platform_body.md`, в формулировке
для этой вкладки:

| ID | Правило | Следствие для конфигуратора |
|---|---|---|
| **P1** | Один аффект: `AffectiveSpace.axes` | YAML описывает *импульс к событию*, не второй вектор чувств |
| **P2** | Только `EmotionalImpulse` + `step` | Хост, GUI, encoder, Dry Run **не** присваивают оси |
| **P8** | Деньги / срочность не оси. Канон из 8 имён закрыт | Теги `закупки, срочность, риск` остаются тегами. Нельзя завести ось `urgency` или `budget` |
| **P9** | Без проекции чувств как управления | Подписи «страх», «радость» — read-only интерпретация |
| **P11** | Params собирает SchemaBinder из `rank_weights()` | Вкладка может *показать* ranking, не может его переопределить в YAML |
| **H9** | Хост не добавляет оси | `ADVANCED_AFFECT_AXES_ENABLED` открывает UI, не расширяет `AXES` |

Замороженные оси, каждая в `[-1.0, 1.0]`:

```
valence, arousal, dominance, stress, trust, curiosity, stability, attachment
```

Readout (не поля YAML):

- `decision_bias()` → `{risk, response_speed, word_choice, empathy, goal_priority}` в `[-1, 1]`
- `rank_weights()` → `{caution, cost_aversion, speed_seek, reliability, novelty_seek, assertiveness}` в `[0, 1]`

Семантика (`src/semantic_emotions.py`): `joy`, `sadness`, `love`, `hate`,
`fear`, `pleasure_rest`. Считается из осей. Не пишется в YAML. Не идёт в
selector / SchemaBinder.

`source` импульса от события мира: всегда `"external"`. Пользователь это
не выбирает. Memory/internal — дело ядра (recall, TD, conflict), не роли.

## 2. Scope и фазы

### Фаза A — вкладка роли + YAML + encoder (эта поставка)

Обязательно в одном PR / одном цикле реализации:

1. Парсер и round-trip YAML: все 8 осей, `intensity`, неизвестные ключи — ошибка.
2. Encoder: когда маппинг *срабатывает*, эмитится `EmotionalImpulse`, не только токены.
3. GUI вкладки: shorthand как сейчас + раскрываемый блок 8 осей + превью readout + семантические ярлыки.
4. Пресеты — YAML-справочник (§4.4): четыре заводских в поставке, свои
   через GUI; клик по пресету заполняет полный канонический вектор.
5. Compose ролей сравнивает полный entry, не только valence/arousal/tags.
6. i18n EN/RU, help, тесты.
7. Флаг `ADVANCED_AFFECT_AXES_ENABLED = True`.

### Фаза B — живой A(t) на карточке сотрудника

Тот же документ, отдельный шаг реализации *после* фазы A:

- На карточке запущенного сотрудника: текущие 8 осей, top-3 semantic
  labels, `decision_bias` / `rank_weights` как числа.
- Источник: `AffectiveSpace.snapshot()` уже существующего
  `EmployeeSession`. Никакого второго state.
- Обновление in-place (не пересоздавать виджеты каждый тик — тот же
  инвариант, что у tick log).
- Dry Run роли по-прежнему **не** стартует `EmployeeSession`.

Фаза B не блокирует приёмку фазы A.

### Вне scope (явно)

- Новые оси, legacy pleasure/pain как поля роли, параллельный VAD.
- YAML-переопределение `decision_bias`, `rank_weights`,
  `_OUTCOME_STATUS_VECTORS`, `DEFAULT_DECISION_MATRIX`.
- Редактор `token_rules` / lexicon на этой вкладке.
- Язык условий «когда quantity < 10» (это WorldState + classifier /
  lexicon, не аффект).
- Переписывание `semantic_emotions.py` / `affective_space.py`.
- Импорт `nowa_sandbox` из `nowa_body`.
- Пресеты внутри `config.yaml` роли (это справочник конфигуратора, не
  данные роли). Encoder и compose пресеты не читают.

## 3. As-built: что сломано относительно канона

Фиксируем, чтобы реализация чинила конкретно это, а не «добавляла UI».

### 3.1 Парсер выкидывает оси

`nowa_body/role_config.py` `_parse_affective_mapping` сохраняет только
`valence`, `arousal`, `tags`. Ручной YAML с `stress:` / `trust:` после
Save из GUI или `load_role_config` теряется. Это нарушение P1: роль не
может задать канонический импульс.

### 3.2 Encoder почти не кормит A(t) из маппинга

Живой путь: `GenericEncoder.encode(world_state)`
(`src/mcp_body/generic_encoder.py`).

- Overlay `_overlay_tokens` при совпадении имени события в haystack
  результатов эмитит `event:…`, `valence:…`, `arousal:…`, `domain:…`.
- `_impulses_for_tool` **не** смотрит в `affective_mapping`. Импульсы:
  `outcome_impulse` на error/timeout, heuristic cost/quantity, novelty.
- `BusinessEventEncoder.encode_tool_result` при classifier возвращает
  **только токены** `_tokens_for_mapped_event`, без impulse.

Итог: вкладка настраивает «как себя чувствовать», а сотрудник на старте
получает эти числа в основном как **контекст памяти/seed**, не как
external impulse. Фаза A обязана закрыть этот зазор.

### 3.3 GUI и контроллер знают только два числа

- Слайдер arousal: `from_=0.0, to=1.0` (удобный shorthand «спокойно →
  тревожно»), канон оси — `[-1, 1]`.
- `upsert_affective_event(name, valence, arousal, tags)` затирает
  остальные оси, если их не пронести через draft.
- Пресеты `AFFECT_PRESETS` зашиты в `gui_configurator_controller.py`
  (четыре id, только valence/arousal). Свои пресеты сделать нельзя;
  правка чисел требует релиза кода.
- Кнопка advanced создаётся и сразу прячется.

### 3.4 Compose сравнивает неполный entry

`role_compose._merge_affective` конфликтует, если отличаются valence,
arousal или tags. Два роли с одинаковыми VA, но разным `stress`, сейчас
сольются молча. После фазы A это compose conflict.

## 4. YAML: схема `affective_mapping` v1.1

Обратная совместимость: существующие роли (только valence/arousal/tags)
валидны без правок. Опущенная ось **не** значит `0.0` — её нет в векторе
импульса.

```yaml
affective_mapping:
  stock_critical_low:
    # shorthand (обязательный минимум, как сейчас)
    valence: -0.70          # [-1, 1]
    arousal: 0.80           # shorthand-слайдер пишет [0, 1];
                            # advanced может записать [-1, 1]
    tags: [procurement, urgency, risk]

    # канон (все ключи опциональны; неизвестные — ошибка загрузки)
    dominance: -0.20
    stress: 0.70
    trust: -0.10
    curiosity: 0.15
    stability: -0.40
    attachment: 0.00

    intensity: 0.35         # [0, 1], default 0.35
                            # encoder для READ-overlay clamp ≤ 0.4 (канон §6.5)
```

### 4.1 Поля entry

| Поле | Тип | Default если ключа нет | Правило |
|---|---|---|---|
| `valence` | float | `0.0` | Всегда в YAML после Save из GUI (shorthand всегда записан) |
| `arousal` | float | `0.5` | То же |
| `tags` | list[str] | `[]` | Доменные ярлыки, не оси. `urgency` / `risk` здесь законны |
| `dominance` `stress` `trust` `curiosity` `stability` `attachment` | float | *omit* | Только канонические имена. Clamp `[-1, 1]` на parse |
| `intensity` | float | `0.35` | Clamp `[0, 1]` на parse. Encoder overlay дополнительно `min(value, MAX_IMPULSE_INTENSITY)` где `MAX_IMPULSE_INTENSITY = 0.4` |

Запрещены в entry:

- любое имя не из `{valence, arousal, dominance, stress, trust, curiosity, stability, attachment, tags, intensity}`;
- legacy `pleasure` / `pain` / `relaxation` / … (ядро их ещё мапит внутри
  `EmotionalImpulse`, роль — нет: держим YAML на каноне);
- `source`, `decision_bias`, `rank_weights`, `emotion`, `label`;
- вложенный блок `axes:` как второй словарь (плоская форма, как shorthand).

Ошибка: `RoleConfigError` с путём
`{path}: affective_mapping['{event}'] unknown key '{key}'` — без
молчаливого drop. Это тот же принцип, что у capabilities: silently
dropped field — класс бага, который проект уже ловил.

Имя события: непустая строка. Рекомендация UI: `snake_case` латиница для
стабильных id (`stock_critical_low`); отображаемое имя может быть RU
через существующий словарь подсказок, **не** отдельное YAML-поле в этой
версии (id события = ключ маппинга = токен `event:{name}`).

### 4.2 Что парсер должен вернуть

```python
{
  "valence": float,
  "arousal": float,
  "tags": list[str],
  # только оси, которые были в YAML:
  "stress": float,          # optional
  ...
  "intensity": float,       # всегда после parse (подставить default)
}
```

Round-trip Save: не дописывать в файл оси, которых автор не задавал.
Если GUI раскрыл advanced и пользователь не трогал `trust`, ключа
`trust` в YAML нет. Явный `trust: 0.0` после движения слайдера — пишется.

Контроллер `upsert_affective_event` расширяется:

```text
upsert_affective_event(name, valence, arousal, tags=None, axes=None, intensity=None)
```

`axes` — dict подмножества шести не-VA осей (и опционально перекрытие
valence/arousal из advanced). Непереданные оси в draft **сохраняются**,
а не обнуляются. Чтобы стереть ось: `axes={"stress": None}` или отдельный
`clear_affect_axis(name, axis)` — GUI кнопка «сбросить ось».

### 4.3 Compose

`_merge_affective`: два entry с одним ключом события совместимы, если
равны (с допуском float `1e-9`) все присутствующие канонические оси,
`intensity` и `tags` (как списки). Иначе `RoleConfigError` compose
conflict, как сейчас для VA.

### 4.4 Справочник пресетов (не роль)

Пресет — именованный шаблон импульса. Клик подставляет числа в
**текущее событие** роли. Это UX-сахар над той же схемой entry, что в
§4.1. Справочник **не** часть `affective_mapping`, **не** едет в
encoder, **не** компонуется между ролями. Справочник **глобальный**:
задал один раз — доступен для любой роли, независимо от того, какая
сейчас открыта. Переключение роли полосу пресетов не меняет и не
перезагружает пользовательский файл из каталога роли.

`AFFECT_PRESETS` в Python после фазы A **не** является источником
истины. Словарь в коде либо исчезает, либо остаётся тонкой обёрткой
`{id: vector}` поверх загруженного YAML — без зашитых чисел.

#### 4.4.1 Два файла

Тот же приём, что у сотрудников: поставка в пакете, пользовательское —
рядом с `nowa_roles/`, GUI туда только и пишет.

| Слой | Путь | Кто пишет |
|---|---|---|
| Поставка | `nowa_body/data/affect_presets.defaults.yaml` (рядом с пакетом, в git) | Разработчик продукта. GUI **никогда** не пишет этот файл |
| Пользователь | sibling `nowa_roles/`, по тому же правилу, что `default_employees_root`: если `roles_root.name == "nowa_roles"`, то `roles_root.parent / "nowa_affect_presets.yaml"`, иначе `roles_root / "nowa_affect_presets.yaml"` | GUI справочника. Файл появляется при первом сохранении своего пресета / оверлея / скрытия |

Если файла поставки нет — это баг упаковки. GUI показывает ошибку и
пустую полосу кнопок; пользователь всё равно может завести свои пресеты
в пользовательский файл. Аварийного словаря чисел в `.py` нет: иначе
снова два источника истины.

Если пользовательского файла нет — в полосе только поставка (четыре
заводских). Это нормальный первый запуск.

Тесты кладут `roles_root` в tmp: пользовательский путь уезжает в tmp,
поставка читается из пакета (или из явно переданного `defaults_path`).

#### 4.4.2 Схема YAML

Одинаковая для обоих файлов. Неизвестные ключи у preset entry — ошибка
загрузки (те же 8 осей + `intensity` + подписи + служебные поля ниже).
Тегов у пресета нет: теги принадлежат событию роли, клик пресета их не
трогает.

```yaml
schema_version: 1
hidden: []          # только пользовательский файл: id заводских, которые
                    # спрятать с полосы (сами данные поставки не удаляются)
order: []           # опционально; если непустой — порядок кнопок
                    # (известные id; неизвестные пропускаются; кто не
                    # перечислен — в хвост в порядке появления)
presets:
  - id: crisis                    # ^[a-z][a-z0-9_]{1,47}$
    label_en: Crisis              # хотя бы одно из label_en / label_ru
    label_ru: Кризис
    valence: -0.80
    arousal: 0.70
    dominance: -0.25
    stress: 0.75
    trust: -0.15
    curiosity: 0.20
    stability: -0.45
    attachment: 0.00
    intensity: 0.35
```

Поля preset entry:

| Поле | Обязательность | Правило |
|---|---|---|
| `id` | да | Уникален внутри файла. В пользовательском файле тот же `id`, что у поставки = **оверлей** (замена чисел/подписей), не вторая кнопка |
| `label_en` / `label_ru` | хотя бы одно | GUI берёт подпись текущего языка; если пусто — второй язык; если оба пусты — `id` |
| 8 осей | как в §4.1 | omit = не подставлять эту ось при клике (не писать 0 в событие) |
| `intensity` | нет | default `0.35` |
| `hidden` на самом пресете | нет | не использовать; скрытие только списком `hidden` верхнего уровня |

В файле поставки **нет** `hidden` / нет пользовательских id. Четыре
заводских id зарезервированы как builtin: `crisis`, `success`,
`trust_break`, `routine`. Их векторы — контракт поставки (§6.1 таблица
= содержимое `affect_presets.defaults.yaml`, расхождение — баг).

Служебный флаг `builtin` в YAML не хранить: он вычисляется при merge
(`id` есть в поставке).

Дубликат `id` в одном файле → ошибка загрузки.

#### 4.4.3 Merge

Модуль `nowa_body/affect_presets.py` (тонкий слой, как `employee_config`):

1. Загрузить поставку. Все id → `builtin=True`.
2. Если есть пользовательский файл — загрузить.
3. Для каждого пользовательского пресета: если id уже в поставке —
   заменить vector/labels (остаётся `builtin=True`); иначе добавить
   (`builtin=False`).
4. Вычесть `hidden` из **полосы кнопок**. Скрытый заводской остаётся в
   справочнике с действием «вернуть на полосу / сбросить к поставке».
5. Порядок: `order` пользовательского файла, иначе поставка в её
   порядке, затем пользовательские id в порядке файла.

Результат merge — то, что рисует полоса и то, что резолвит
`apply_affect_preset(event_name, preset_id)`.

Запись: **только** пользовательский файл. Оверлей заводского id пишется
туда целиком (все поля, которые пользователь оставил после правки).
Сброс заводского к поставке = удалить этот id из `presets` и из
`hidden` пользовательского файла. Удаление своего пресета = убрать id из
пользовательского файла. «Восстановить всю поставку» = удалить
пользовательский файл (с подтверждением: пропадут и свои пресеты —
тогда лучше две кнопки: «сбросить заводские оверлеи» vs «удалить все
свои»). Минимум фазы A: сброс **по одному** id и удаление своего;
полная очистка пользовательского файла — с отдельным подтверждением.

Save роли и Save справочника **независимы**. Клик пресета пачкает draft
роли (`dirty=True`). Правка справочника сразу (или по OK диалога) пишет
YAML справочника и не требует Save роли.

#### 4.4.4 Применение к событию

`apply_affect_preset` копирует в текущий event:

- все оси, которые есть в пресете (включая явный `0.0`);
- `intensity`;
- **не** копирует tags;
- оси, которых в пресете нет, в событии **не** затирает (как upsert
  extra-осей).

Если нужно «как в пресете, без хвостов от прошлого» — в диалоге
справочника опция «заменить все оси» (сначала `clear` extra, потом
копия). Default клика на полосе — мягкая подстановка § выше, как сейчас
слайдеры переезжают, а теги живут своей жизнью.

Нет `preset_id` в YAML события: после клика событие не помнит шаблон.
Это намеренно (событие — истина роли; справочник можно поменять завтра).

## 5. Encoder: маппинг → импульс

### 5.1 Контракт импульса

Когда событие `E` из `affective_mapping` **сработало** на этом тике:

```python
impulse = {
    "vector": {axis: value, ...},  # только оси, заданные в entry
                                   # valence/arousal всегда, если есть в entry
                                   # (после parse они есть всегда)
    "intensity": min(entry.intensity, MAX_IMPULSE_INTENSITY),
    "source": "external",
}
```

Дальше существующий `apply_impulses(..., source="external")` →
`AffectiveSpace.step(external_impulses=...)`. Никаких присваиваний.

Не подставлять опущенные оси нулями в `vector`: ноль в векторе — это
импульс «держись у нуля по этой оси», omit — «не трогай».

### 5.2 Когда событие считается сработавшим

Не вводить новый язык условий. Три существующих канала, все должны
эмитить **и токены, и импульс**:

1. **Classifier (предпочтительный).**
   `event_classifier(tool_id, payload)` вернул имя `E`, и `E` есть в
   mapping. Сегодня `BusinessEventEncoder.encode_tool_result` отдаёт
   только токены — фаза A добавляет impulse в тот путь, которым реально
   пользуется runtime (`encode` / encode+classifier), а не оставляет
   impulse только в мёртвой ветке.

2. **Overlay haystack (as-built GenericEncoder).**
   Имя `E` или `event:E` встречается в сериализованных READ-результатах
   тика. Поведение токенов не менять. Добавить параллельный
   `_impulses_for_mapped_event(E)`.

3. **WRITE outcome.**
   Не дублировать маппинг события. Status → только
   `AffectiveSpace.outcome_impulse(status, magnitude)`. Роль не
   переопределяет таблицу §6.6. На вкладке — read-only справка
   (см. §6.4).

Одно событие на одном тике — один overlay-импульс (не дважды из
classifier и haystack). Дедуп по имени `E` внутри `encode()`.

Канон §6.5: READ-импульсы слабые, `intensity ≤ 0.4`. Heuristic
cost/quantity/novelty **остаются**. Маппинг — overlay *добавка*, не
замена heuristics. Если на тике сработали и heuristic, и mapping — оба
идут в `step` (сумма импульсов — штатное поведение ядра).

### 5.3 Токены

Совместимость seed / памяти:

- как сейчас: `event:{E}`, `valence:{bucket}`, `arousal:{bucket}`,
  `domain:{tag}`;
- **не** плодить `emotion:fear` как токен управления (P9);
- дополнительные оси **не обязаны** становиться токенами в фазе A
  (импульс несёт числа). Опционально, если понадобится поиск по памяти:
  `axis:{name}:{low|mid|high}` с теми же порогами, что valence
  (`|x|≤0.15` mid, иначе знак). Не блокер приёмки.

`event_to_tokens` (seed wizard) остаётся на valence/arousal/tags, чтобы
не сломать существующий корпус. Extra axes в уроке не требуются: урок
помнит *событие*, A(t) сдвинет encoder в рантайме.

### 5.4 Превью ≠ live A(t)

Превью на вкладке (фаза A):

1. Новый `AffectiveSpace()` (все оси 0, кроме внутренних baseline ядра).
2. Один `step(external_impulses=[impulse_from_entry])`.
3. Показать `axes`, `decision_bias()`, `rank_weights()`.
4. `SemanticEmotionsLayer().update_from_space(space)` → top-3 по
   `activation`, подпись «интерпретация, не команда».

Подпись в UI: это ответ на вопрос «если сотрудник был в покое и случилось
только это событие, куда сдвинется решение». Это **не** текущее чувство
живого сотрудника (фаза B).

Реализация превью — функция в `gui_configurator_controller` (или тонкий
хелпер рядом с encoder), которая импортирует `AffectiveSpace` /
`SemanticEmotionsLayer` из ядра. GUI не считает формулы bias сам.

### 6.1 Shorthand (верх, всегда виден)

Без изменения смысла GUI spec §5:

- Valence слайдер `[-1, 1]`, шаг `0.05`.
- Arousal shorthand слайдер **`[0, 1]`**, шаг `0.05` — «спокойно /
  тревожно». Пишет поле `arousal`. Это сознательное сужение UX: типичные
  рабочие события лежат в неотрицательном arousal.
- Если в YAML `arousal < 0` (задали в advanced), shorthand показывает
  `0.00`, блок advanced **раскрыт**, под слайдером текст: «задан полный
  arousal ниже нуля — смотрите продвинутую настройку». Движение
  shorthand-слайдера перезаписывает `arousal` неотрицательным значением
  (пользователь явно выбрал упрощённую шкалу).

Пресеты на этой вкладке — кнопки из **справочника §4.4**, не литералы в
коде. Полоса перестраивается при изменении справочника, не каждый poll
сотрудника.

- Клик по кнопке = `apply_affect_preset` к текущему событию (полный
  вектор из YAML справочника, теги не трогает).
- Кнопок столько, сколько видимых пресетов после merge. Если больше
  ~8 — полоса переносится на вторую строку; сверх ~16 остаток только в
  диалоге «Справочник» (на полосе — видимые по `order`).
- **Сохранить как пресет** — диалог: id, подпись RU, подпись EN.
  Вектор берётся с текущих слайдеров события. Пишет пользовательский
  YAML. Если id совпал с заводским — это оверлей (предупреждение:
  «заменит поставку Кризис, пока не сбросите»). Если id свой и уже
  есть — подтверждение перезаписи.
- **Справочник…** — отдельное окно (не вкладка роли):

```

│  (те же слайдеры осей + intensity, что на вкладке)          │
│                                                             │
│  [Применить к событию] [Сохранить] [Скрыть с полосы]        │
│  [Сбросить к поставке]     — только builtin                 │
│  [Удалить]                 — только свой                    │

```

Заводские четыре нельзя удалить из поставки через GUI. Их можно скрыть
с полосы, переопределить числами, сбросить к файлу поставки.

Таблица ниже — **контракт файла поставки**
`affect_presets.defaults.yaml`. Реализация копирует эти числа в YAML,
не в Python.

| Пресет (id) | RU / EN | valence | arousal | dominance | stress | trust | curiosity | stability | attachment | intensity |
|---|---|---|---|---|---|---|---|---|---|---|
| `crisis` | Кризис / Crisis | −0.80 | 0.70 | −0.25 | 0.75 | −0.15 | 0.20 | −0.45 | 0.00 | 0.35 |
| `success` | Успех / Success | +0.80 | 0.60 | +0.20 | −0.35 | +0.40 | 0.15 | +0.25 | +0.10 | 0.30 |

Числа — рекомендуемые стартовые импульсы, не «научная норма». Знаки и
какие оси задеты менять в поставке только осознанно (кризис бьёт
stress/stability, разрыв доверия бьёт trust, успех поднимает trust и
снижает stress). Подписи RU/EN живут в YAML справочника, не в
`gui_configurator_i18n.py` (ключи i18n остаются у кнопок «Справочник»,
«Сохранить как пресет», help).

Пользователь может подвинуть что угодно после клика — это уже поля
события роли, пока не нажмёт Save роли.

Кнопка **Удалить событие** (сейчас есть в контроллере, в UI нет):
подтверждение, затем `remove_affective_event`. Seed-уроки, ссылающиеся на
`event:{name}`, после удаления ловятся уже существующей валидацией роли
(не молча). Это не удаление пресета.

### 6.2 Продвинутая настройка

- Progressive disclosure: свёрнуто по умолчанию, если в entry нет ни
  одной extra-оси и `intensity` равен default `0.35`. Раскрыто, если
  extra-оси заданы, `arousal < 0`, или `intensity ≠ 0.35`.
- Шесть слайдеров `[-1, 1]` + опциональный полный arousal `[-1, 1]`
  (синхронизирован с shorthand, когда arousal ≥ 0).
- У каждой extra-оси: «сбросить» → ключ исчезает из YAML.
- Неподписанные оси в свёрнутом виде пользователю не показываются списком
  нулей.
- Короткие подписи осей (i18n), не лекция. Help-кнопка вкладки объясняет
  «это сдвиг чувства, не приказ сотруднику грустить».

Синхронизация shorthand ↔ advanced: правка valence/arousal в любом месте
пишет те же два поля. Extra-оси от shorthand не выводятся автоматически
(не додумывать `stress = −valence`). Если автор хочет stress — двигает
stress. Пресет из справочника — место, где extra-оси заполняются пакетом;
свои шаблоны автор заводит там же, не в коде.

### 6.3 Превью-блок

Read-only, пересчёт при любом движении слайдера / пресете / смене
события (в памяти draft, до Save — как остальные поля вкладки).

Не показывать сырой JSON. Показывать:

- до трёх semantic labels с `activation` ≥ порога слоя (как в
  `SemanticEmotionsLayer`; если ни одного — «нейтрально / нет ярлыка»);
- пять чисел `decision_bias`;
- шесть чисел `rank_weights`.

Формулировка P9 в help и одной строке под превью: ярлыки описывают
состояние, сотрудник по ним **не** ветвится.

### 6.4 Справка по outcome (read-only)

Компактная таблица из канона §6.6 (`accepted/success/ok`,
`rejected/failed/error`, `timeout/unknown`). Без редактирования.
Зачем: чтобы автор роли не пытался на этой вкладке «нарисовать» успех
заказа как событие `deal_closed_favorable` *вместо* платформенного
outcome — оба канала законны и **складываются**, если сработают вместе.

### 6.5 Help и i18n

Обновить `help.affect.body` EN и RU:

- два слайдера = быстрый ввод;
- продвинутая настройка = остальные оси канона;
- превью = гипотетический сдвиг решения;
- пресеты = справочник, четыре заводских поставляются, свои можно
  сохранить с текущих слайдеров;
- теги не являются осями;
- Save роли и сохранение справочника — разные действия;

Новые ключи (имена ориентировочные, стиль существующего
`gui_configurator_i18n.py`): `affect.advanced`, `affect.reset_axis`,
`affect.intensity`, `affect.preview`, `affect.preview_hint`,
`affect.outcome_help`, `affect.delete_event`, `affect.save_preset`,
`affect.preset_catalog`, `affect.preset_builtin`, `affect.preset_overlay`,
`affect.preset_hide`, `affect.preset_restore`, плюс подписи восьми осей и
шести rank keys / пяти bias keys. Подписи заводских пресетов — в YAML
поставки, не в i18n. Паритет EN/RU обязателен для ключей UI.

Флаг `ADVANCED_AFFECT_AXES_ENABLED` после фазы A равен `True`. Сам флаг
можно оставить как выключатель на случай отката, но default — включено.
Скрывать блок целиком больше нельзя: иначе спецификация снова «не
закрыта».

## 8. Инварианты реализации

**A1.** GUI не валидирует YAML роли сам. Save роли → `load_role_config` /
`validate_role_config`. Справочник пресетов валидирует
`affect_presets.py` (тот же принцип: ошибка с путём, не silent drop).
Tk не парсит YAML руками.

**A2.** Никакого `axes[k] = v` в `nowa_body`, encoder, employee host.

**A3.** `GenericEncoder` не импортирует роль-классы. Mapping — данные.

## 11. Критерий готовности (фаза A)

- Вкладка позволяет задать любой канонический импульс к событию и
  сохранить его в YAML так, что `load_role_config` его не откусит.
- Живой encoder сдвигает A(t) через `EmotionalImpulse`, когда событие
  сработало.
- Автор роли видит, как это ударит по `decision_bias` / `rank_weights`,
  и видит semantic labels как подпись, не как ручку управления.
- Четыре заводских пресета поставляются YAML-ом и видны на полосе без
  пользовательского файла. Пользователь может сохранить свой пресет,
  переопределить заводской, скрыть, сбросить и удалить свой — без правки
  Python.
- `AFFECT_PRESETS` с зашитыми числами в коде больше не источник истины.
- Outcome MCP по-прежнему платформенный.
- Старые роли и seed-корпус зелёные.
- EN/RU паритет help и подписей осей.
- Тесты T1–T22 зелёные.

Фаза B не входит в этот DoD.
